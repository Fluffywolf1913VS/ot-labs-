# Methodology

## 1. Establish a passive baseline

Traffic was captured from the distribution switch on the HMI-facing interface:

```text
Node: sw-distribution
Interface: eth4
Port: 502
Host: 172.18.1.21
```

The normal HMI pattern was a periodic FC03 request/response cycle:

```text
172.18.1.30 → 172.18.1.21  FC03 Read Holding Registers
172.18.1.21 → 172.18.1.30  FC03 Response
```

The request started at raw register address `0` with a word count of `28`, producing a read window of addresses `0–27`.

## 2. Use one controlled HMI action at a time

To avoid ambiguous mappings, a single HMI variable or command was changed while recording Modbus/TCP traffic.

Examples:

- Level SP: `60 → 61`
- Outlet Flow SP: `200 → 201`
- Inlet valve: Open / Close / Stop
- Outlet valve: Open / Close / Stop

## 3. Isolate writes

Useful Wireshark display filter:

```text
modbus.func_code == 6
```

This exposed FC06 writes generated by the HMI. The raw register address and UINT16 value were recorded for each action.

## 4. Correlate process values with FC03 reads

Useful filter:

```text
modbus.func_code == 3 && ip.src == 172.18.1.21
```

The Modbus server responses were compared with HMI values displayed at approximately the same time.

## 5. Assign confidence levels

- **Confirmed** — a controlled HMI action caused a specific FC06 write and/or was repeatable with unambiguous semantics.
- **Strong correlation** — FC03 values closely tracked the HMI but were not isolated with a unique controlled write.
- **Unknown** — insufficient evidence.

This distinction is important in reverse engineering: a plausible match should not be presented as proven without evidence.
